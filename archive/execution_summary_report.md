  - 行AllDifferent: 256個
  - 列AllDifferent: 256個
  - 宮AllDifferent: 256個
  - 已知數字: 55個

### 性能瓶頸
1. **排列選擇約束**: 每行需要ExactlyOne(排列選擇變數)約束
2. **排列-值映射**: 每個排列需要與行位置值變數建立映射
3. **記憶體需求**: 約需數GB記憶體

### 建議優化策略
1. **分塊編碼**: 先編碼基本數獨約束，後加入排列約束
2. **隱式約束**: 使用CP-SAT的AddAllowedAssignments替代顯式排列約束
3. **增量求解**: 先求解基本約束，再添加排列約束

## 3. SAT DIMACS 編碼分析

### 編碼規模
- **變數數**: ≈1,115,590（基本4096 + 排列選擇111萬）
- **子句數估算**: 
  - 基本約束: ≈26萬
  - 排列選擇: ≈1,111,494×16/2 ≈ 889萬（兩兩互斥）
  - 排列-值映射: ≈1,111,494×16 ≈ 1,778萬
  - **總計**: ≈2,700萬子句

### 記憶體溢出原因
- 兩兩互斥約束 O(n²) 對於111萬排列變數產生約10¹²個子句
- 需要使用更高效的編碼（如序數編碼、卡塔蘭編碼）

### 優化編碼策略
```
推薦方案:
1. 使用序數編碼（Cardinality Networks）
   - 將ExactlyOne編碼從O(n²)降至O(n log n)
2. 使用At-Most-One的Lingeling編碼
   - 僅需O(n)個輔助變數和子句
3. 分離編碼
   - 先編碼基本數獨約束（4096變數）
   - 再添加排列約束（分塊處理）
```
