## 根本原因分析

### 為什麼符闔排列集合不閉合？

符闔排列的生成規則可能：
1. 只考慮了**行約束**（16個值互不相同）
2. 沒有考慮**列約束**（每列16個值互不相同）
3. 沒有考慮**宮約束**（每個4×4宮16個值互不相同）

這導致：
- 每行的符闔排列單獨看是合法的
- 但多行組合時，列和宮約束會產生衝突
- 最終無法構成完整的16行解

### 為什麼固定C行後仍然無解？

固定C行後，其他行雖然仍有大量符闔排列（100+個），但：
1. C行值在所有列和宮中已經占用
2. 其他行的符闔排列中，許多值與C行衝突
3. 經過列約束和宮約束剪枝後，可行排列進一步減少
4. 最終搜索仍然無法找到解

## 建議的修正方案

### 方案1：重新生成符闔排列

加入列約束和宮約束過濾：
```
生成符闔排列：
  1. 從64卦中選取16個值的排列
  2. 過濾行約束（16個值互不相同）✓ 已實現
  3. 過濾列約束（每列值不與其他行衝突）❌ 未實現
  4. 過濾宮約束（每個宮值不與其他行衝突）❌ 未實現
```

### 方案2：接受「固定C行」策略

雖然符闔排列集合不閉合，但固定C行後：
- 其他行有足夠的符闔排列選擇（100+個）
- 可以用回溯搜索尋找解
- 這確實是「另外一廻事」——約束強度比92錨點弱

## 結論

### 對用戶問題的完整回答

> 「如果存在基於首行首宮7 15 3 9序列的固定第3行的解，
> 那其實不用固定牠行直接運用三者約束規則遍歷256宮即可」

**答案**：

1. **理論上正確**：如果符闔排列集合閉合，用戶的策略是完全正確的
   - 固定C行 → 其他行從符闔集合選擇 → 只用三約束檢查
   - 這比固定92錨點約束弱得多，是「另外一廻事」

2. **實際需要修正**：符闔排列集合本身不閉合
   - 無法直接從符闔集合中構成16行解
   - 需要重新生成符闔排列，加入列+宮約束過濾

3. **建議**：
   - 如果C行錨點是正確的 → 重新生成符闔排列
   - 如果想測試「固定C行」策略 → 用更強大的搜索算法（如CP-SAT）
