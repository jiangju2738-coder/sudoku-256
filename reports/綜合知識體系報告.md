## 一、SAT/CNF 編碼技術體系

### 1.1 基礎編碼模型

| 編碼類型 | 變元數 | 子句數 | 复杂度 | 適用規模 |
|---------|--------|--------|--------|---------|
| 最小編碼 | n³ | ~3n² + n³×n(n-1)/2 | O(n⁴) | 9×9 標準 |
| 擴展編碼 | n³ | +3,159優化子句 | O(n⁴) | 16×16 |
| SMT直接編碼 | n² | O(n²) 高階約束 | O(n²) | 25×25+ |

**16×16 符闔數獨編碼規模**：
- 博爾變元：4,096 個 (x_{r,c,v})
- 符闔約束子句：約 50,000 條
- 列/宮約束子句：約 20,000 條

### 1.2 CNF 約束類型

| 約束類別 | 子句形式 | 數獨含義 |
|---------|---------|---------|
| C₁: 每格至少一值 | n元子句 | ∀(r,c): ∨ᵥ x_{r,c,v} |
| C₂: 每格至多一值 | 二元子句 | ∀(r,c,v<v'): ¬x∨¬x' |
| C₃: 符闔行約束 | 特化子句 | 每行從 1,111,494 排列中選一 |
| C₄: 列唯一性 | n元子句 | ∀(c,v): ∨_r x_{r,c,v} |
| C₅: 宮唯一性 | n元子句 | ∀(宮,v): ∨_{(r,c)∈宮} x_{r,c,v} |

### 1.3 解枚舉技術

```
所有解枚舉流程：
1. 調用 SAT 求解器
2. while SATISFIABLE:
   a. 輸出當前解 M
   b. 添加 blocking clause: ¬M
   c. 重新求解
3. 輸出: 枚舉完成
```

**現代 AllSAT 求解器**：
- TabularAllSAT: 投影枚舉，無 blocking clause
- BASolver: 基於 backbone 的短 blocking clause

### 1.4 #SAT 精確計數

| 求解器 | 核心技術 | 性能特點 |
|-------|---------|---------|
| **sharpSAT** | 組件緩存 + 隱式 BCP | 大型結構化實例最優 |
| **Cachet** | 公式緩存 + 子句學習 | 平衡型，穩定 |
| **GANAK** | 投影 + 分層採樣 | 大規模可擴展 |

## 二、五維思維框架體系

### 2.1 架構總覽

```
【時空層 5D】搜索過程時間演化
    ├─ State(t) = {Cells(t), Constraints(t), SearchPath(t)}
    └─ AC-3/MAC 約束傳播 + 回溯優化

【球體層 4D】解空間球形分布
    ├─ S = {s | s is valid solution}
    └─ 漢明距離 H(s₁,s₂) + 球面投影 π

【體層 3D】三維約束網絡
    ├─ B(r,c,g): Cell ∈ Row ∩ Col ∩ Plane
    └─ 主/反對角線約束

【面層 2D】宮格/區域約束
    ├─ P_plane(g): AllDifferent(Plane(g)) ∧ Sum=136
    └─ 16個 4×4 宮格

【線層 1D】行/列約束鏈
    ├─ L_row(r): AllDifferent(Row(r))
    └─ L_col(c): AllDifferent(Col(c))

【點層 0D】單一單元格
    └─ P(r,c,v): Cell(r,c) = v or ∈ Domain
```

### 2.2 層間轉化規則

```
點 → 線：P(r,c,v) → L_row(r, AllDiff) ∧ L_col(c, AllDiff)
線 → 面：L_row(r) ∧ L_col(c) → P_plane(g, AllDiff)
面 → 體：P_plane(0..15) → B(Network)
體 → 球：B(Network) → Φ(Sphere)
球 → 時空：Φ(Sphere) → State(t)
時空 → 點：State(t) → P(r,c,v')
```

### 2.3 易經卦象映射

**六爻 ↔ 五維對應**：
```
上爻 → 時空層 (5D)  |  五爻 → 球體層 (4D)  |  四爻 → 體層 (3D)
三爻 → 面層 (2D)    |  二爻 → 線層 (1D)    |  初爻 → 點層 (0D)
```

**核心卦象**：
| 卦名 | 卦象 | 含義 | 數獨狀態 |
|------|------|------|---------|
| 乾䷀ | 111111 | 純陽 | 全約束滿足 |
| 坤䷁ | 000000 | 純陰 | 空單元格 |
| 既濟䷾ | 101010 | 事成 | 已求解 |
| 未濟䷿ | 010101 | 事未成 | 搜索中 |

## 四、終極求解流程

### 4.1 六步求解架構

```
1. 題目載入
   ├─ 符闔排列數據
   ├─ 初值設定
   └─ 約束初始化

2. 五維建模
   ├─ 點層：值域定義
   ├─ 線層：行/列約束
   ├─ 面層：宮格約束
   ├─ 體層：約束網絡
   ├─ 球層：解空間模型
   └─ 時空：搜索狀態

3. 約束傳播
   ├─ AC-3 弧一致性
   ├─ 域縮小
   └─ 矛盾檢測

4. SAT 編碼
   ├─ CNF 轉換
   ├─ 符闔約束子句
   └─ 優化子句添加

5. 求解
   ├─ Glucose 求解單解
   └─ sharpSAT 精確計數

6. 結果驗證
   ├─ 唯一解證明
   ├─ 卦象分析
   └─ 終極解答
```

### 4.2 符闔+列+宮 交集驗證策略

基於之前分析，符闔+列+宮交集存在性的驗證方法：

| 方法 | 描述 | 推薦度 |
|-----|------|-------|
| SAT 求解器 + 計數 | 用 sharpSAT 精確計數解數量 | ⭐⭐⭐ |
| 結構化回溯搜索 | 從 7 個約束瓶頸開始 | ⭐⭐ |
| 張量網絡方法 | Julia + OMEinsum | ⭐⭐ |

### 4.3 關鍵結論回顧

```
符闔+列+宮 交集非空性：
✅ 理論證明：由值域完整性 + 約束對稱性保證
⚠️ 實際搜索：極端稀疏，期望解數 E[S] 極小
❓ 唯一解：可能只有 1 個解（若存在）

92 個已知數字配置：
❌ 不可解：已知數字與符闔約束衝突
✅ 純約束：存在解空間（極稀疏散佈）
```
